# 1. 行业痛点

> 园区、交通枢纽、产线、仓库 24×7 值守——传统监控只是"眼睛"，不"思考"。

| 痛点 | 现状 | 我们能做的 |
|------|------|-----------|
| 人力不足 | 100 路摄像头 3 班倒仍漏报 | 1 套 AI 持续盯防所有路数 |
| 反应滞后 | 发现问题 → 调阅录像 → 派人核验，分钟级 | 端到端告警 < 3 秒 |
| 误报多 | 移动侦测、绊线设置脆弱 | 语义级行为识别，过滤树叶 / 阴影 |
| 证据散失 | 报警时再去拉流，片段已被覆盖 | 自动取证 + 短视频 + 写入 MinIO |
| 模型固化 | 装完即定型，新场景需返厂 | 现场抽帧 → 标注 → 增量训练 → 热加载 |
| 数据孤岛 | 视频只是视频 | 检测事件 → Kafka → BI / 工单联动 |

# 4. 技术架构

### 前后端分离 + 微服务推理 + 消息总线 + 对象存储

---

## 4.1 架构总览

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  浏览器       │───▶│  Django API  │───▶│  PostgreSQL  │
│  Vue3 + hls.js│    │  + WebSocket │    │  (5434)      │
└──────────────┘    └──────────────┘    └──────────────┘
       │                    │                    ▲
       │ HLS                 │ Redis 6379/2       │
       ▼                    ▼                    │
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  MediaMTX     │◀──│  yolo-service │───▶│  MinIO S3    │
│  RTSP/HLS     │   │  FastAPI+YOLOv8│   │  取证/飞轮    │
└──────────────┘    └──────────────┘    └──────────────┘
       ▲                    │                    ▲
       │ RTSP 拉流            │ Kafka 9092          │
       │                    ▼                    │
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  IP 摄像头     │   │  RabbitMQ    │    │  runtime     │
│  / NVR / 推流  │   │  5672         │   │  编排/取证/训练 │
└──────────────┘    └──────────────┘    └──────────────┘
```

---

## 4.2 技术栈一览

| 层 | 选型 | 关键理由 |
|----|------|---------|
| 前端 | Vue 3 + TS + Element Plus + Vite 5 | 生态成熟，HMR 快 |
| 可视 | ECharts、hls.js、Day.js | 大屏深色 / 后台浅色双主题 |
| 后端 | Django 5 + DRF + Channels (WebSocket) | 一体化 API + WS |
| 数据 | PostgreSQL（`USE_SQLITE=1` 可回退） | 关系型主库 |
| 缓存 | Redis DB 2 | 告警去重 / 任务队列 / 帧缓存 |
| 推理 | Ultralytics YOLOv8 + FastAPI | 工业级 SOTA + 异步服务化 |
| 流媒体 | MediaMTX（RTSP :8554 / HLS :8888） | 浏览器原生 HLS 播放 |
| 消息 | Kafka `yolov8.detect.frames`、RabbitMQ `evidence/notify/flywheel` | 高吞吐帧 + 业务任务 |
| 对象存储 | MinIO（Bucket `yolov8pro`） | S3 兼容、本机自托管 |

# 7. 部署方案

### 单机起步 · 集群扩展 · 全离线可用

---

## 7.1 部署形态

| 形态 | 适用 | 资源建议 | 说明 |
|------|------|---------|------|
| **单机一体** | 试点 / PoC | 16C / 32G / RTX 3060+ / 1TB | 全部进程同机，docker compose 一键起 |
| **标准 3 节点** | 中型园区（≤200 路） | API / 推理 / 存储 各 1 台 | 推理独立 GPU 节点 |
| **集群** | 大型 / 多园区 | K8s + 推理 Pod 水平扩展 | yolo-service 无状态，可多副本 |

## 7.2 操作系统与依赖

- Windows 10/11 / Windows Server 2022（开发友好）
- Linux Ubuntu 22.04 / CentOS 8+（生产推荐）
- Docker 24+ / Docker Compose 2.20+
- GPU 驱动 + CUDA 12+（推理节点）
- 网络：摄像头可达 RTSP，浏览器可达 3000/3001

---

## 7.3 硬件建议（单机一体试点）

| 部件 | 规格 | 用途 |
|------|------|------|
| CPU | 16 核 x86_64 | Django + runtime + MediaMTX |
| 内存 | 32 GB | Redis 缓存 + 推理 batch |
| GPU | RTX 3060 12G 或 A4000 | YOLOv8 推理 |
| 存储 | 1 TB SSD + 4 TB HDD | 系统 / 取证视频 |
| 网络 | 千兆 ×2 | 摄像头网段 + 业务网段 |

# 8. 性能与可用性

---

## 8.1 关键指标

| 指标 | 数值 | 测试条件 |
|------|------|---------|
| 端到端告警延迟 | < 3 秒 | RTSP→推理→Kafka→告警落库 |
| 单 GPU 并发路数 | 16 路 @ 2 FPS | YOLOv8n + RTX 3060 + 720p |
| 单 GPU 并发路数 | 8 路 @ 5 FPS | YOLOv8s + RTX 3060 + 720p |
| HLS 切片时长 | 1 秒 | MediaMTX hlsSegmentDuration |
| 浏览器首帧 | < 2 秒 | 720p + hls.js + 千兆内网 |
| 告警去重窗口 | 可配（默认 60s） | Redis SETEX |
| 系统冷启动 | < 90 秒 | docker compose up |
| API 平均响应 | < 200 ms | PostgreSQL 索引齐全 |

---

## 8.2 高可用与容灾

- **推理微服务无状态化**：水平扩展，单实例崩溃自动重启
- **任务队列持久化**：RabbitMQ 镜像队列 / Kafka 多副本
- **证据冗余**：MinIO EC 模式 + 异地 bucket 复制
- **数据库**：PostgreSQL 流复制 + 定期 pg_dump
- **失败兜底**：
  - Kafka 不可用 → yolo-service HTTP 回调 Django ingest
  - 推理服务不可用 → `YOLO_INFER_MODE=local` Django 进程内推理
  - 单进程兜底 → `DJANGO_EMBEDDED_RUNTIME=1` 一体化部署

# 9. 飞轮自学习

### 这是与传统 AI 视频厂商最大的差距

---

## 9.1 飞轮闭环

```
   ┌──────────────────────────────────────────────┐
   │                                                │
   ▼                                                │
摄像头画面                                            │
   │                                                │
   ├──> yolo-service 推理                            │
   │         │                                       │
   │         ├──> 命中 → 告警 + 自动抽帧入库         │
   │         └──> 不确定 → 抽帧入库（待标注）         │
   │                                                 │
   ▼                                                 │
yolov8pro/flywheel/dataset/auto/{images,labels}      │
   │                                                 │
   ▼                                                 │
标注台 /flywheel（人工改框 / 改类）                   │
   │                                                 │
   ▼                                                 │
通过审核 → 移入训练集                                 │
   │                                                 │
   ▼                                                 │
runtime 排队微调（增量训练 from best.pt）             │
   │                                                 │
   ▼                                                 │
验证集 mAP50 不下降 → yolo-service 热加载新权重 ──────┘
                       │
                       └──> 否则保持旧权重 + 记录回滚
```

---

## 9.2 飞轮价值

- **客户自助**：现场人员标注 → 一键微调 → 模型自动迭代
- **风险可控**：mAP50 不下降才上线，回滚机制保留旧权重
- **数据资产**：所有现场数据沉淀在客户自己的 MinIO，不外流
- **零返厂**：新场景 / 新类别无需厂商二次进场，运营成本骤降
- **可量化**：每次微调记录权重路径、mAP、训练样本数

> **传统厂商模型固化 vs 我们飞轮闭环 = 持续变聪明的系统 vs 越用越旧的系统**
